# Destination guide

Choose the least powerful persistent form that solves the recurring need.

| Destination | Use when | Avoid when |
|---|---|---|
| Global instructions | A stable, cross-cutting preference or safety boundary affects many tasks. | The direction is domain-specific or needs a substantial procedure. |
| Codex skill | A reusable capability needs specialized judgment, a defined workflow, or optional supporting resources. | It is merely a single always-on preference. |
| `AGENTS.md` | A rule is specific to one repository, product, or directory tree. | The work happens across unrelated projects. |
| Script or utility | Inputs and transformation are deterministic and repeated. | Judgment, changing external context, or approval is central. |
| Template or checklist | Output structure or a small review routine repeats, but execution remains human judgment. | A fuller skill or tool is required. |
| Automation | A bounded recurring event has a clear trigger, authority, and failure behavior. | The user needs to review each instance or inputs are ambiguous. |
| Personal memory | A durable preference, fact, or prior decision is repeatedly needed as context. | It contains sensitive, obsolete, or task-specific material. |
| Ad hoc | Evidence is thin, the pattern is temporary, or standardization would add more cost than benefit. | The same stable process is repeatedly reconstructed. |

When an existing skill, rule, or utility already covers the need, recommend a small extension or better invocation guidance rather than a parallel artifact.
